## ネットワークの全体像と実習環境構築

---

# 1-1. ネットワークの全体像と階層モデル

* **LAN（Local Area Network）**：オフィスや自宅など限定された範囲のネットワーク
* **WAN / インターネット**：複数のLAN同士を相互接続した巨大なネットワーク
* **なぜ「階層（レイヤ）」に分けるのか？**
  * 通信の役割を分担し、機器やソフトの入れ替え・障害切り分けを簡単にするため

| TCP/IP階層 | 主な役割 | 代表的な機器・技術 |
| :--- | :--- | :--- |
| **アプリケーション層** | ユーザーにサービスを提供 | Web (HTTP), DNS, メール |
| **トランスポート層** | データを適切なアプリへ届ける・信頼性確保 | TCP, UDP, ポート番号 |
| **インターネット層** | 別のネットワークへ経路を選んで届ける | IP, ルータ, ICMP |
| **ネットワークインタフェース層** | 同じLAN内の隣り合う機器へ届ける | イーサネット, MACアドレス, スイッチ |

---

# 1-1. ハンズオン演習：実習環境のセットアップ

3. **コマンドプロンプト（端末画面）を開く**
   * `PC1` をクリック → Desktop / Terminal からコマンド画面を開き、`ipconfig`（または `ip a`）を実行

# Day 1 - 2限目（70分）
## MACアドレスとスイッチの基本動作

**本日のゴール：**
1. MACアドレスの構造と役割を説明できる
2. スイッチが通信先を学習・転送する仕組みを動作確認できる

---

# 1-2. MACアドレスとL2スイッチの仕組み

* **MACアドレスとは？（48ビット / 16進数表記）**
  * 例：`00:1A:2B:3C:4D:5E`（ネットワーク機器に固有の物理アドレス）
  * 前半24ビット＝メーカー識別子（OUI）、後半24ビット＝シリアル番号
* **L2スイッチの3つの基本動作**
  1. **学習（Learning）**：届いたフレームの「送信元MACアドレス」と「受信ポート」を表に記録
  2. **フラッディング（Flooding）**：宛先MACが表にない場合、受信ポート以外の全ポートへ一斉送信
  3. **フィルタリング／転送（Forwarding）**：表に宛先MACがあれば、該当ポートだけにピンポイント送信

---

# 1-2. ハンズオン演習：スイッチの学習動作を観察

> **演習ミッション（40分）：** 3台のPCをスイッチにつなぎ、MACアドレステーブルの変化を見よう

1. **トポロジ作成とIP設定（仮設定）**
   * `PC1`, `PC2`, `PC3` を `Switch1` に接続
   * それぞれに `192.168.1.1` / `192.168.1.2` / `192.168.1.3`（マスク `255.255.255.0`）を設定
2. **学習前のテーブル確認**
   * スイッチのCLIで `show mac address-table` を実行（最初は空であることを確認）
3. **通信発生とテーブルの変化**
   * `PC1` から `PC2` へ `ping 192.168.1.2` を実行
   * 再度スイッチで `show mac address-table` を実行し、`PC1` と `PC2` のMACアドレスが登録されたことを確認（`PC3` は未登録！）

---

# 1-2. まとめ・確認ポイント

* **今日の重要キーワード**
  * **MACアドレス**：同じLAN内で機器を識別するための固有番号
  * **MACアドレステーブル**：スイッチが「どのポートの先にどの機器がいるか」を覚えるメモ帳
* **セルフチェック**
  * [ ] まだ一度も通信していない `PC3` のMACアドレスがテーブルに載っていない理由を説明できるか？

---

# 1-3. ARPとICMP（ping）の役割

* **なぜARPが必要なのか？**
  * 人間やアプリは「IPアドレス」で相手を指定するが、LAN内のスイッチは「MACアドレス」しか見ないため、**IPアドレス → MACアドレスの変換**が必要
* **ARPの流れ**
  1. **ARPリクエスト（ブロードキャスト）**：「`192.168.1.2` の人、MACアドレスを教えて！」と全員に聞く
  2. **ARPリプライ（ユニキャスト）**：「私です。MACは `AA:BB:...` です」と本人が返信
  3. 結果は一定時間 **ARPキャッシュ（ARPテーブル）** に保存される
* **ICMP（ping）**：相手が生きているか確認するための「エコー要求（Echo Request）」と「エコー応答（Echo Reply）」

---

# 1-3. ハンズオン演習：pingの裏側をパケット観察

> **演習ミッション（40分）：** シミュレーションモードでARPとICMPの動きを1ステップずつ追跡しよう

1. **ARPキャッシュの初期化**
   * `PC1` のコマンド画面で `arp -a` を実行し、現在のキャッシュを確認（必要なら `arp -d` でクリア）
2. **シミュレーション（パケット追跡）モードへ切替**
   * 表示フィルタを `ARP` と `ICMP` のみに設定
3. **pingの実行とステップ観察**
   * `PC1` から `PC2`（`192.168.1.2`）へ `ping` を実行
   * 1発目に **ARPリクエストが全PCへ飛ぶ様子** と、その後 **ICMPが往復する様子** を観察
   * 2回目の `ping` ではARPが省略されることも確認

---

# Day 2 - 1限目（70分）
## IPアドレス設計とサブネットマスク

**本日のゴール：**
1. IPアドレスの「ネットワーク部」と「ホスト部」を区別できる
2. サブネットマスクを使って「同じネットワークか別か」を判定できる

---

# 2-1. IPアドレスとサブネットマスクの基本

* **IPv4アドレス（32ビット）**：8ビットずつ4つに区切って10進数表記（例：`192.168.10.1`）
* **ネットワーク部とホスト部**
  * **ネットワーク部**：どのグループ（LAN）に属するかを表す住所の「市区町村」
  * **ホスト部**：そのグループ内のどの機器かを表す「番地」
* **サブネットマスクの役割**：どこまでがネットワーク部かを区切る線
  * `255.255.255.0`（`/24`）：最初の3つ（24ビット）がネットワーク部、最後の1つ（8ビット）がホスト部
  * ホスト部が **すべて0** ＝ ネットワークアドレス（例：`192.168.10.0`）※PCに設定不可
  * ホスト部が **すべて1** ＝ ブロードキャストアドレス（例：`192.168.10.255`）※PCに設定不可

---

# 2-1. ハンズオン演習：IP設計と通信可否の実験

> **演習ミッション（40分）：** 同じスイッチにつないだPC同士でも、ネットワーク部が違うと通信できないことを確かめよう

1. **演習問題（紙・メモ帳で計算：10分）**
   * `192.168.50.0/24` で使えるPC用IPアドレスの範囲と、ブロードキャストアドレスを答える
2. **実験トポロジの構築（30分）**
   * `PC1`：`192.168.1.10` / `255.255.255.0`
   * `PC2`：`192.168.1.20` / `255.255.255.0`
   * `PC3`：`192.168.2.10` / `255.255.255.0`
   * 全員同じ `Switch1` に接続し、`PC1` から `PC2` と `PC3` へ `ping` を実行
   * なぜ物理的につながっているのに `PC3` へ届かないのかを確認

# Day 2 - 2限目（70分）
## デフォルトゲートウェイとルータの役割

**本日のゴール：**
1. デフォルトゲートウェイが必要な理由を説明できる
2. ルータを1台配置し、異なる2つのネットワーク間で通信を成功させる

---

# 2-2. ルータとデフォルトゲートウェイの仕組み

* **ルータの役割**：異なるネットワーク（サブネット）同士を相互接続する機器
  * ルータの**ポート（インタフェース）ごとに異なるネットワークのIPアドレス**を持つ
* **デフォルトゲートウェイ（Default Gateway）とは？**
  * PCから見て「自分のネットワークの外へ出るときに最初に荷物を預ける出口（ルータのIP）」
* **通信の流れ（PC1 → ルータ → PC3）**
  * PC1は宛先IPが別ネットワークだと判断すると、**宛先MACアドレスにルータのMAC**を入れて送信する

---

# 2-2. ハンズオン演習：2つのLANをルータでつなぐ

> **演習ミッション（40分）：** ルータ1台を使って `192.168.1.0/24` と `192.168.2.0/24` を通信させよう

1. **トポロジ構成**
   * 左側LAN（`192.168.1.0/24`）：`PC1`（`.10`）— `Switch1` — `Router1 (G0/0: .254)`
   * 右側LAN（`192.168.2.0/24`）：`PC2`（`.10`）— `Switch2` — `Router1 (G0/1: .254)`
2. **ルータの基本設定（CLI）**
   ```text
   enable
   configure terminal
   interface gigabitEthernet 0/0
    ip address 192.168.1.254 255.255.255.0
    no shutdown
   interface gigabitEthernet 0/1
    ip address 192.168.2.254 255.255.255.0
    no shutdown
